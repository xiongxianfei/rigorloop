The existing catalog now owns execution constraints, dependencies and literal normalized command/adapter bases. Closed unit/mode/resource/phase values, unknown selected fields, mismatched commands, duplicate identities, missing dependencies and cycles reject before launch. Missing isolation resolves visibly to serial command execution. Only the selected skill-validator and adapter-regression command scopes have a current bounded assessment: their writable fixtures/output are owned temporary trees, immutable repository inputs are read, environment mutations are process-local, teardown owns its directories, children execute sequentially and no shared external service is needed. Other old parallel allowlist entries are conservatively serial pending their actual audit. No naming-based independence claim is retained.

The scheduler runs dependency-ready work with serial barriers, continues independent failures by default and stops queued work immediately when fail-fast observes a failed parent or timeout. Focused/preflight failure prevents dependent boundary work; selector-supplied phase relabeling cannot bypass catalog phase ownership. Default selected jobs are capped at four and nested wrappers receive their parent's allocation. Native Node test invocations receive an explicit allocated concurrency value; opaque whole suites remain exclusive until M4 audit.

Task streams are separate scratch files, decoded and displayed in bounded chunks; missing or undecodable successful output cannot become a pass. Selection-order results preserve actual duration, argv, signal/timeout/unavailable/not-started meaning and rerun commands. Temporary invocation scratch is scoped to the wrapper call.

Linux execution combines POSIX groups, per-task subreaper supervisors and `/proc` parent/birth identities to terminate and reap owned descendants, including fast double forks that open new sessions and replace their environment. Each supervisor adopts only its task’s orphans and remains alive until they are reaped; no environment-token attribution remains. An atomic early command outcome stops fail-fast launches during cleanup and preserves actual pass/failure independently of cleanup duration. The supervisor uses a four-second grace within the parent’s five-second termination window, then kills/reaps survivors. A preexisting unrelated child remains untouched. Platforms where this implementation cannot establish descendant ownership fail before launching; domain validators remain directly runnable. Process isolation is not a security sandbox.
