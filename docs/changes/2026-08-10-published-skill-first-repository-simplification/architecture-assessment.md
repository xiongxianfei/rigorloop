# Architecture Assessment

Assessment: architecture-required

## Rationale

The approved spec changes long-lived ownership and dependency direction across canonical skills, packaged resources, generated adapters, installer materialization, CI composition, release verification, and lifecycle governance.
It also defines the removal boundary for selectors, caches, schedulers, target-runtime behavior evidence, semantic validators, and duplicate governance parsers.

Architecture must identify the current components that become Gate A, Gate B, Gate C, and the single governance entry point; define composition and failure propagation; separate semantic review from deterministic validation; and define migration seams and rollback boundaries before a multi-slice execution plan can be safe.

## Result

Proceed through `architecture` and `architecture-review` before planning.
