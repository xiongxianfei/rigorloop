# Learn skill semantic preservation review

## Result

The final package preserves the accepted learning contract while narrowing ownership. No material rule is deleted without a disposition, and no destination authority moves into `learn`.

## Universal behavior retained inline

- periodic or explicit triggering and non-default lifecycle role;
- thin-evidence, single-event, systemic-gap, and maintainer-direction boundaries;
- contributor confirmation as classification authority only;
- sensitive-data minimization;
- canonical session and topic paths;
- required-resource failure, stops, handoff, and claim limitations;
- exact operation selection and bounded route-result write authority.
- portable direct-invocation wording without a Codex-only `$skill` requirement.

## Conditional behavior retained in the reference

- ordered `Frame -> Observe -> Classify -> Route` method;
- cadence and incident evidence selection;
- deterministic suffix selection and absence recheck;
- complete first write and fail-closed partial-record handling;
- observation/evidence distinctions and no-observation outcomes;
- closed classifications and confirmation states;
- topic curation, idempotency, and conflict stops;
- complete stable route rows, immutable completion kinds, settlement meanings, and aggregate reporting.

## Ownership correction

The focused amendment and `specs/learn-artifact-model.md` now agree: `learn` writes sessions, confirmed topic guidance, and exact route backlinks. Proposal, spec, ADR, workflow, skill, issue, tracker, plan, and external-system owners remain the only writers of their destinations. Owner-produced authoritative outcomes remain mandatory where the classification requires them.

## Compatibility and exclusions

Historical sessions remain readable and unchanged but cannot become route-result targets without separate migration. The existing learn namespace, no-template direction, topic non-authority, pre-session trigger closeout, and compatibility-sensitive phrases remain present. No target-agent execution, transcript grading, tokenizer dependency, learning engine, polling service, recovery transaction, or new persistent owner was added.

## Evidence

- closed rule and literal ledgers plus unknown-value fixtures;
- 28+ deterministic scenario contracts;
- focused M2 operation/session/route tests;
- legacy learn artifact-model validator coverage;
- full skill-validator and package-build suites;
- independent M2 code review with three findings corrected and clean rereview.
