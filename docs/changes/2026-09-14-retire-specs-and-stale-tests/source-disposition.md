## Complete test and fixture assessment boundary

The baseline has 235 files under tests/fixtures (adapters 16, artifact-lifecycle 46, change-metadata 3, documentation-prose 13, release-transaction 28, review-artifacts 41, rigorloop-records-v3 2, skills 86). This is not the complete fixture population: scripts/fixtures, package-local fixtures, inline data, helpers and dynamically constructed cases are equally in scope. The 21 scripts/test-*.py and 22 CLI .test.js files are entrypoint counts, not case counts. Neither count is a deletion target.

Implementation must enumerate the actual test runners/catalog/jobs and their discovered cases, input builders and readers before relying on reduced coverage. Assign retained current protection, refined setup/assertions, or explicit retired/redundant outcome; for grouped decisions, account for every member and exception. Inspect assertions and actual consumers, not only names, age, imports or test-spec membership. Wording-only checks may be stale; a parser-sensitive public literal or current regression may remain necessary. An invalid historical record can prove current rejection without becoming operational compatibility. Generated cases cannot be declared covered from a file count.

Milestone evidence records concrete old/new case identities or sufficiently exact grouped membership, current requirement/hazard, retained detection or retirement basis, fixtures/readers and commands actually run. It is acceptable to retain most of a useful suite; it is not acceptable to leave it unassessed. No permanent case ledger, new validator platform or mandatory metric is introduced. Final reconciliation accounts for additions and removals since baseline, proves an empty specs tree, and names no unresolved in-scope stale-test family.
