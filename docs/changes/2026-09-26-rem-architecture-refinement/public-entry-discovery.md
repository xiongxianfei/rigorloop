## Governing mapping contract

The facet's `observed.public_entries` records the public `name`, navigational `group`, concise `purpose`, `source_path`, and detailed `contract` reference. A command additionally names its owning Interface `operation`; a skill entry does not invent a public API. The entries are subordinate records scoped by their owning facet. Source observations do not establish package qualification.

A reasoned `proposed` choice may contain `public_entry_mappings`. Each mapping refers to one observed `entry` and records `functions`, whose `function`, `relation`, and `contribution` explain the proposed correspondence. The closed relation vocabulary is `guides`, `invokes`, and `realizes`. `limits` preserve incomplete specialist translation and interpretation boundaries. Every entry has exactly one mapping; an empty Function list requires an explicit substantive limit. An entry's name identifies its local catalog record, not a new governed REM entity.

`guides` means the published procedure directs a participant's performance of behavior. `invokes` means the entry requests behavior through its execution path. `realizes` means an implementation contribution is proposed as realizing the Function. None of these mappings is a new Function allocation, scenario execution edge, assurance judgment, or runtime observation. They remain engineering analysis even when the public name is observed in source.

Features derive from `Feature.realized_by`; accountable Modules derive from `Function.allocated_to`, preserving explicit unallocated dispositions. Catalog placement must not transfer all specialist behavior to MOD-012 or all command behavior to MOD-010. IF-004 remains provided by MOD-018; IF-008 remains only the adopted REM authoring-guidance branch.
