## Test cases

### T1. Accept exactly the closed modes

- Covers: R1, example.mode.closed, acceptance.mode.closed
- Level: unit
- Command IDs: none
- Fixture/setup: A normalizer invocation fixture with input text `A`.
- Steps: Invoke the normalizer once with mode `trim` and once with mode `preserve`.
- Expected result: Both invocations are accepted and return a text result; accepted-mode enumeration contains exactly `trim` and `preserve`.
- Failure proves: The accepted mode vocabulary is missing a required mode or contains an additional mode.
- Evidence artifact: not applicable
- Automation location: planned test implementation
- Required by milestone: not applicable

### T2. Trim every Unicode White_Space code point at text boundaries and preserve it internally

- Covers: R2, EC1, example.trim.whitespace, acceptance.trim
- Level: unit
- Command IDs: none
- Fixture/setup: Deterministically enumerate exactly `U+0009`, `U+000A`, `U+000B`, `U+000C`, `U+000D`, `U+0020`, `U+0085`, `U+00A0`, `U+1680`, `U+2000`, `U+2001`, `U+2002`, `U+2003`, `U+2004`, `U+2005`, `U+2006`, `U+2007`, `U+2008`, `U+2009`, `U+200A`, `U+2028`, `U+2029`, `U+202F`, `U+205F`, and `U+3000` as the Unicode `White_Space` set; use retained non-whitespace sentinels `A` and `B`.
- Steps: For each enumerated code point `W`, invoke `trim` with `WA`, `AW`, `WAW`, `W`, and `AWB`; also invoke it with a string containing the complete enumerated sequence before `A`, after `A`, and between `A` and `B`.
- Expected result: Each leading or trailing `W` is removed; an input containing only `W` returns empty text; every `W` between retained `A` and `B` remains unchanged and in order; the complete boundary sequence is removed while the complete internal sequence is preserved unchanged and in order.
- Failure proves: At least one Unicode `White_Space` code point is not removed at a text boundary, internal whitespace is removed or changed, or boundary handling depends incorrectly on an individual code point or sequence position.
- Evidence artifact: not applicable
- Automation location: planned parameterized test implementation
- Required by milestone: not applicable

### T3. Preserve input text unchanged

- Covers: R3, EC2, example.preserve.unchanged, acceptance.preserve
- Level: unit
- Command IDs: none
- Fixture/setup: Inputs include empty text, non-whitespace text, and text containing the complete Unicode `White_Space` enumeration from T2 at leading, internal, and trailing positions.
- Steps: Invoke `preserve` for each input and compare the returned text code point-for-code point with the input.
- Expected result: Every invocation returns text exactly equal to its input, including order, multiplicity, and position of all whitespace code points.
- Failure proves: Preserve mode changes, removes, inserts, or reorders input text.
- Evidence artifact: not applicable
- Automation location: planned parameterized test implementation
- Required by milestone: not applicable

### T4. Reject every unknown mode with no text

- Covers: R4, EC3, example.mode.unknown, acceptance.mode.unknown
- Level: unit
- Command IDs: none
- Fixture/setup: Deterministically generate the representable mode vocabulary under test and exclude exact values `trim` and `preserve`; include empty, case-substituted, prefixed, suffixed, and otherwise distinct values where those values are representable by the normalizer interface.
- Steps: Invoke the normalizer with input text `A` for every generated unknown mode.
- Expected result: Every invocation fails with exactly `unknown-mode` and returns no text.
- Failure proves: An unknown mode is accepted, produces a different failure, or returns text.
- Evidence artifact: not applicable
- Automation location: planned exhaustive or property-based test implementation over the representable mode vocabulary
- Required by milestone: not applicable

### T5. Compose mode classification with its required outcome

- Covers: R1, R4, interaction.mode.outcome
- Level: unit
- Command IDs: none
- Fixture/setup: Input text ` A `; exact modes `trim` and `preserve`; the unknown-mode set generated by T4.
- Steps: Invoke the normalizer for both exact accepted modes and every generated unknown mode, then classify each observable result as returned text or failure without text.
- Expected result: `trim` and `preserve` are the only modes producing text; every other mode produces exactly `unknown-mode` and no text.
- Failure proves: Mode classification and outcome handling disagree, including an accepted mode taking the unknown outcome or an unknown mode reaching a text-producing path.
- Evidence artifact: not applicable
- Automation location: planned parameterized test implementation
- Required by milestone: not applicable
