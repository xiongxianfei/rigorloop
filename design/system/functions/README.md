# Functions

A Function represents logical system behavior, independently of its physical implementation wherever practical.
It may contribute to several [Features](../features/README.md).

The collection uses one `<FUNC-ID>-<title-slug>.json` file per Function under the [asset naming convention](../../support/README.md#entity-naming-and-filenames).
Names and behavior descriptions belong in the entity content, independently of its stable identity.
The current analysis defines 73 Functions. The confirming and constraining SR views below are derived from requirement references; they are not separately authored Function fields.
The accountable Module column is a view of each Function's canonical `allocated_to` reference or explicit deferred allocation; the four new local-history Functions are unallocated. All allocations remain draft target-architecture decisions.
