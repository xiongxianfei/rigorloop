# Applicable authoring guidance and task assessment

[MOD-008](module.json) owns FUNC-032–034 and AR-079–081 under SR-032–034. Its [authoring composition](authoring.md) retains activity ownership; canonical REM methods remain the source of engineering rules. This document defines proposed Design for IR-006, including source selection, bounded explanations and prepared task assessment. It does not report participant performance or qualified installed skills.

## Guidance selection and coherence

A participant identifies the requested activity, project/model scope, declared adopted method/profile and version, participant context, available sources, and any previously used guidance. MOD-008 contributes selection and explanation through MOD-017's [IF-008](../../../../interfaces/IF-008-applicable-engineering-authoring-guidance/interface.json). MOD-012 composes that result into the invoked specialist activity; a human may apply the same method directly. Missing project adoption cannot be supplied by installing a skill.

Resolve each required concept, method, representation rule and relevant worked example against its accountable source. The selection records activity, declared profile/version, each source's owner, locator and exact inspected content identity, applicability reasoning, and whether the material is normative or illustrative. A version label alone does not identify changed local content. A caller-supplied immutable package or inspected source snapshot can supply this basis; unavailable exact content remains a gap. The logical selection is an attributable author-prepared account, not a new schema, automatic compatibility database or permission to fetch remote material.

The accountable author inspects the declared profile and source scope to explain applicability. Human explanations and agent resource references use this same selected basis. They may differ in length and navigation, but must expose all rules, conditions and failure boundaries needed for the requested task. An example illustrates a rule and cannot override it. Missing required context or a relevant worked example is reported with its owner and affected activity; complete applicable guidance is not claimed from a directory listing alone.

On a profile, activity or material source change, compare the previous selection to the new basis before continuing dependent explanation or assessment. Identify superseded, incompatible, unavailable and unresolved material separately. A source revision does not by itself prove incompatibility; record the actual applicability reasoning. Do not silently choose latest guidance, mix versions or reinterpret historical task observations under current rules. If sources change during preparation, use the captured basis or mark the affected preparation unresolved and prepare it again; never label a mixed read as one coherent selection.

## Bounded authoring and correction

Use the selected method to connect supplied inputs to an expected engineering outcome. The explanation names the governing rule, source and selected version, relevant illustrative step, proposed result, applicable checks, unresolved decisions and responsible next action. [Requirement Analysis](requirement-analysis.md) owns need/obligation changes; [Engineering authoring](design-authoring.md) owns System and Architecture Design detail. Guidance does not silently replace these owners.

A correction begins with an identifiable finding, affected definition and inspected model state. Explain which rule the finding violates and how the proposed correction can be assessed. If a diagnostic cannot be connected to that basis, expose the missing link instead of inventing a fix. Model edits, reference resolution and validation execution remain with their existing owners; a recommendation does not perform them. Changed subjects require fresh inspection before applying the recommendation.

For a rename, distinguish stable identity and semantic parentage from display name or storage path. Explain affected current references and containment; a proposed move that changes parentage is a separate semantic decision. For retirement, identify surviving obligations/dependencies and their dispositions and preserve recoverable original meaning through the state-control owner. No old date, closed Change or passing format check authorizes deletion.

Where author-provided context leaves a material decision unresolved, state its effect and the highest-value clarification needed while retaining the other known uncertainty. Continue only independent supported analysis. Existing authority can support the next action; guidance must not create a redundant approval request or treat unanswered clarification as a decision. Unsupported representations allow explicitly bounded conceptual work, without a conformance or implemented-support claim.

### Illustrative worked example and method navigation

The following fictional local batch-import example is explanatory content, not a RigorLoop requirement, approved customer design or observed task result. The example assumes a declared profile with the eight draft entity representations available. A different profile must be checked rather than inheriting that assumption. For an actual invocation, bind the linked canonical sources to the inspected selection described above.

An operator needs every valid row in a local batch to be retained together, or none if any row is invalid. The seven [5W2H](../../../../../../rem/methods/5w2h.md) answers are: **What:** avoid partial imported batches; **Why:** partial data misleads later work; **Who:** operator and downstream readers; **When:** on an authorized import request; **Where:** the selected local project store; **How:** accept only a completely valid batch with an explicit result; **How much:** all rows in the selected finite batch, with no invented performance threshold. This supports a candidate IR and an SR requiring all-or-none retention; the SR has exactly that one IR parent. The author must confirm that need before treating the example as applicable to a real project.

## Prepared semantic task assessment

The guidance maintainer supplies the assessment scope before task performance: participant group (new REM author with basic engineering knowledge, experienced author/reviewer, or agent), guidance/profile and exact source selection, task inputs and subject state, expected semantic output, required governing-rule explanation, applicable checks, declared assistance conditions, and intended observations. MOD-008 organizes this domain-specific task context under FUNC-034. The maintainer is accountable for the expected outcome; it must not be generated from the candidate answer being assessed.

Cover requirement 5W2H and parentage, black-box Scenario and Feature/Function distinctions, AR/Function allocation and Interface interaction, identity-preserving rename, reference correction and obligation-preserving retirement. The worked example above supplies a common small fixture, but each actual task identifies its own supplied records and independently specified expectation. Preserve material negative conditions such as a structurally valid answer with wrong ownership or a plausible answer lacking a rule explanation. A subset is an explicitly bounded assessment, not a complete profile evaluation.

The participant performs only the authorized supported task and explains the rule from the selected guidance. The observer supplies actual output, explanation, check outcomes, guidance actually used, task occurrence, participant context, ambiguities, additional help and any interruption. Missing observations are not adverse observations and must remain unassessed. Unsupported formats separate conceptual observations from unperformed conformance work. Structural validity alone cannot establish a semantic outcome.

MOD-008 compares supplied observations with the prepared expectations and returns attributable task-specific results and findings through IF-008. Successful reporting requires the expected semantic outcome, passed applicable checks and an adequate rule explanation without conversation-only context. Incorrect output or explanation is unsuccessful; missing checks or observations leaves the dependent result unassessed. Undocumented assistance prevents an independent-completion claim. Declared extra help remains visible even when the eventual outcome succeeds, and an assisted result cannot be presented as unassisted. Keep results for participant groups and exact versions separate; no time target, pass-rate threshold, universal usability conclusion or population inference is introduced.

Changed expected outcomes or guidance create a new assessment basis. Keep earlier observations under the basis actually used; do not change an expected result after seeing an answer to manufacture success. Reassessment identifies actual new work, reusable observations with explicit applicability and the unperformed remainder. An interrupted attempt preserves observed tasks and names what remains unassessed; resumption does not automatically repeat edits or renew earlier success.

### Assurance and retention cooperation

MOD-008 supplies domain-specific prepared task context and the maintainer's task comparison; it does not own generic evidence applicability or formal Review/Verification policy. MOD-012 carries that explicit content to MOD-017's existing [IF-014](../../../../interfaces/IF-014-assurance-content-preparation/interface.json), realized by MOD-007 under [assurance-content.md](../MOD-007-engineering-verification-and-assurance/assurance-content.md). Method definitions, occurrences, coverage, applicability and judgments remain distinct. IF-010 supports current claim reliance, and any formal judgment is supplied by its accountable assessor under applicable independence rules. This author/observer-mediated exchange creates no hidden MOD-008-to-storage write.

For governed retention, MOD-012 uses existing IF-004 tasks, supported native fields and exact supporting attachments when task detail lacks a field. Confirm actual retention through selected readback; a prepared task, attempted save or lost receipt supplies no saved-result claim. On changed record revision or relevant subject basis, reread and reassess the proposed content before retrying. Unknown effects remain explicit; no automatic replay or replacement store. Standalone use retains the same semantic account in an explicitly selected artifact with an accountable writer and observed outcome, without requiring CLI adoption. No chosen working or retained mechanism means no claim that the account was saved.

The semantic assessment is a prepared evaluation technique when guidance quality is being assessed; it is not a new mandatory gate, automated judge or recurring participant execution for every repository validation. Independent specialist review can assess the Design of this procedure. Successful participant performance requires actual task observations and remains separate evidence.

## Realization, rationale and coverage

The selected realization is participant-assisted local guidance and assessment. Canonical REM concepts/methods and subordinate owned explanations remain Markdown and declared model records; authored public skill sources stay under `skills/` and their generated resource packaging remains MOD-013's responsibility. MOD-012 supplies invocation and resource access, not a new inference engine. This Design defines the semantic procedure and illustrative content; it neither edits published skills nor claims that an installed package carries the new procedure. Any later product delivery must reconcile and qualify the selected sources and generated resources.

A selection or task packet is an inspectable working account in the participant workspace. When retained for reliance, its meaningful source basis, expectations, actual observations, contrary results and limitations follow the existing assurance retention contract. Source changes invalidate an unexamined currentness claim, not the historical meaning of the earlier account. No new database, network service, browser assessor or wire schema is needed. Human/agent presentations are alternative consumers of one meaning; separate normative copies would allow version drift. An automatic semantic judge would require additional reliability evidence and is not selected.
