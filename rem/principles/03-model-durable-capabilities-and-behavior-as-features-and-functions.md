# Principle 3: Model durable capabilities and behavior as Features and Functions

## Relationship and why

A stakeholder capability or logical behavior can remain relevant across several requirement revisions and Changes. Giving that capability or behavior its own definition lets engineers relate evolving obligations to it without treating every new request as a new system asset. A concrete usage situation supplies context for the capability; it does not exhaust its meaning.

## REM commitment

IR analysis confirms stakeholder-visible Features, SR analysis confirms logical Functions, and these assets evolve across requirements and Changes. Scenarios provide usage context but do not replace the durable Feature.

## Application

The [System Design model](../models/system-design.md) owns Features and Functions, the [Scenario model](../models/scenarios.md) owns usage situations, and [Functional Analysis](../methods/functional-analysis.md) confirms behavior from obligations.
