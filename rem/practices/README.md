# REM Practices

Practices coordinate Concepts, Principles, Models and Methods around an engineering goal. Each operating Practice contains local stage summaries, procedures, explanations, checks and fallback actions. Current REM rules apply within those stages; the canonical Models and Methods remain their owners. The stages can be revisited and do not replace a project's review or approval workflow.

| Goal | Operating Practice |
| --- | --- |
| Take a bounded outcome from request through design and assessment | [Engineer a change](engineer-a-change.md) |
| Reconstruct intent, behavior, responsibility and evidence for an existing system | [Review an existing system](review-an-existing-system.md) |
| Distinguish appropriate obligations, specified conformance and intended-use success | [Verify and validate a bounded slice](verify-and-validate-a-bounded-slice.md) |
| Compare architecture mechanisms and make a supported choice | [Make an architecture decision](make-an-architecture-decision.md) |
| Improve the right knowledge owner from an observed difficulty | [Improve REM through actual use](improve-rem-through-actual-use.md) |

The supporting [Understand REM guide](understand-rem/README.md) explains how knowledge owners cooperate. The [worked example — inspect responsibility offline](WORKED-EXAMPLE.md) applies current rules through an illustrative design and assessment plans. Its identities are local to the example, and its planned results establish no actual product or user outcome. Release-publication fragments in the Practices are separate illustrations of reasoning and interaction gaps.
