# Source and repository method

Load this method when source selection, freshness, repository-first investigation, external evidence, or citation requires more guidance.

## Repository first

When the fact may already be governed or observable locally, inspect approved artifacts, source, dependency manifests and lockfiles, schemas, generated code, tests, CI, deployment configuration, and prior decisions before external sources. Record exact paths or stable identifiers without copying unnecessary raw data.

## External sources

Match source type to the question. Prefer official documentation, standards, upstream source or release notes, authoritative vendor material, and primary technical evidence. Use secondary explanations or community discussions only when they add relevant observations and label their limitations.

For volatile facts, record the publication or effective date and the access date. Cross-check when one source has material incentives, ambiguous scope, or uncertain freshness. Preserve applicable quotation, citation, licensing, privacy, and source-use constraints.

## Conflicts and gaps

When sources disagree, do not average them into certainty. Explain the scope, version, jurisdiction, environment, or timing difference when evidence supports it. Lower confidence or stop when the conflict cannot be resolved responsibly and could change the decision.
