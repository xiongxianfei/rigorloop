# GitHub Workflow Authoring

Load this reference only after the root selects GitHub create or revise. The root owns authority, safety, classifications, commits, stops, and claims.

## Ownership

The risk map decides what must run and its required execution boundary. This reference serializes that settled mapping into GitHub Actions events, filters, jobs, `if` expressions, matrices, dependencies, and steps. It MUST NOT independently choose PR-versus-boundary placement, invent commands, declare risk coverage sufficient, approve privileged design, or override a mapping conflict.

## Ordinary composition

Bind the exact path, operation, structure, commands, and settled mapping. Creation or authorized structural replacement fills the skeleton; ordinary revision preserves validated organization while composing one complete file. Serialize only approved events and scopes. Filters require mapped coverage. Use read-only permissions, evidenced elevations, project concurrency, bounded timeouts, approved actions, deterministic installation, and stable-key caches. Validate syntax, references, permissions, fork/secret behavior, and mapping agreement before conditional commit.

## Approved privileged realization

Bind one exact current approved design and approving review to the same repository and target. Implement explicitly specified events, scope, permissions, credentials/OIDC, runner class, environments, secrets/forks, actions, and validation exactly. A missing field may retain a compatible universal safe default; otherwise stop. Do not broaden or infer the design.

The skeleton is structural input only. It never authorizes privileged triggers, runners, credentials, permissions, environments, secrets, or jobs.

## Conflict and failure

Stop on a missing project command, incomplete or stale risk mapping, mapping/composition disagreement, unapproved action reference, unsafe fork/secret path, design mismatch, unfilled placeholder, or syntax/identity uncertainty. Report the exact owner needed for correction.
