# Migration and compatibility verification

Use this method when old and new states, formats, clients, records, rollout, rollback, or migration coexist.

Partition supported prior, current, migrated, historical, contradictory, and unknown inputs. Allocate forward migration, mixed-version behavior, rollback or recovery, and read-only historical interpretation to safe milestones. Require identity preservation and fail-closed handling where ambiguity would expand authority.

Use change-level verification for the complete old-to-new workflow when milestone-local checks cannot prove interoperability or recovery.
